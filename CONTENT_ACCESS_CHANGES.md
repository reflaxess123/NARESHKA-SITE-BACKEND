# 📖 Открытый доступ к контенту

## 🎯 Описание изменений

Система контента и теории теперь доступна для неавторизованных пользователей. Пользовательские данные (прогресс) отображаются только для авторизованных пользователей.

## ✅ Изменения в API

### Content API (`/api/content/`)

#### Открытые эндпоинты (без авторизации):

- `GET /api/content/blocks` - Список блоков контента
- `GET /api/content/blocks/:id` - Конкретный блок контента
- `GET /api/content/categories` - Список категорий контента

#### Защищенные эндпоинты (требуют авторизации):

- `PATCH /api/content/blocks/:blockId/progress` - Обновление прогресса

### Theory API (`/api/theory/`)

#### Открытые эндпоинты (без авторизации):

- `GET /api/theory/cards` - Список карточек теории
- `GET /api/theory/cards/:id` - Конкретная карточка теории
- `GET /api/theory/categories` - Список категорий теории

#### Защищенные эндпоинты (требуют авторизации):

- `GET /api/theory/cards/due` - Карточки к повторению
- `PATCH /api/theory/cards/:cardId/progress` - Обновление прогресса
- `POST /api/theory/cards/:cardId/review` - Повторение карточки
- `GET /api/theory/cards/:cardId/stats` - Статистика по карточке
- `POST /api/theory/cards/:cardId/reset` - Сброс прогресса
- `GET /api/theory/cards/:cardId/intervals` - Интервалы повторения
- `GET /api/theory/stats` - Общая статистика

## 🔄 Логика работы

### Для неавторизованных пользователей:

- Доступ к содержимому контента и карточек теории
- **НЕ** включается информация о прогрессе
- Операции с прогрессом возвращают 401 ошибку

### Для авторизованных пользователей:

- Полный доступ ко всем функциям
- Включается информация о прогрессе в ответах
- Доступны операции с прогрессом

## 📋 Структура ответов

### Неавторизованный пользователь - блок контента:

```json
{
  "id": "block_id",
  "fileId": "file_id",
  "file": { "id": "...", "webdavPath": "...", ... },
  "blockTitle": "Заголовок",
  "textContent": "Содержимое...",
  "codeContent": "код...",
  // ... остальные поля блока
  // НЕТ progressEntries
}
```

### Авторизованный пользователь - блок контента:

```json
{
  "id": "block_id",
  "fileId": "file_id",
  "file": { "id": "...", "webdavPath": "...", ... },
  "blockTitle": "Заголовок",
  "textContent": "Содержимое...",
  "codeContent": "код...",
  // ... остальные поля блока
  "progressEntries": [
    {
      "id": "progress_id",
      "solvedCount": 3,
      "createdAt": "...",
      "updatedAt": "..."
    }
  ]
}
```

### Аналогично для карточек теории:

- Неавторизованные: только содержимое карточки
- Авторизованные: содержимое + `progressEntries` с полной информацией о прогрессе

## 🛡 Безопасность

- Все проверки авторизации выполняются на сервере
- Используется middleware `attachUserRole` вместо `isAuthenticated`
- Пользовательские данные никогда не передаются неавторизованным
- Операции с прогрессом требуют явной авторизации

## 🚀 Преимущества

1. **SEO-дружелюбность** - контент индексируется поисковиками
2. **Демо-доступ** - пользователи могут ознакомиться с материалами
3. **Мотивация регистрации** - для сохранения прогресса нужна авторизация
4. **Гибкость** - система адаптируется под роль пользователя

## 📝 Миграция фронтенда

Фронтенд должен:

1. Проверять наличие `progressEntries` в ответах
2. Показывать кнопки прогресса только авторизованным
3. Предлагать регистрацию при попытке сохранить прогресс
4. Обрабатывать 401 ошибки для операций с прогрессом
